# CPU experiment

The interpreter recognizes these specific encodings only:

- `90` NOP and `f4` HLT, used as an experimental stop sentinel rather than a faithful privileged instruction.
- Unprefixed `89/8b/01/03/29/2b/31/33/39/3b/85` register-direct forms: 32-bit MOV/ADD/SUB/XOR/CMP/TEST over the eight legacy registers. Arithmetic and MOV write a zero-extended result; CMP and TEST preserve the full register. 32-bit REX register forms are not supported.
- Unprefixed `89/8b` MOV between r32 and m32, `c7 /0 imm32` MOV to r32/m32, and `8d` LEA r32: support base, SIB, displacement and RIP-relative memory addressing; r32 writes zero-extend, LEA truncates to 32 bits. `c7` RIP-relative addressing uses the end of the full instruction including its immediate. No 32-bit REX extensions are implemented.
- Unprefixed `01/03/29/2b/31/33/39/3b/85` with memory ModRM: 32-bit ADD/SUB/XOR/CMP in both directions and TEST, using the same effective addressing as MOV. Unprefixed `83 /0,/5,/7 imm8` supports register and memory operands, with signed immediate. Read-modify-write memory forms require read and write permission; failed reads or writes do not commit flags or CPU state. CMP and TEST only read. These operations are not host-atomic and do not implement LOCK.
- `b8..bf imm32` and `41 b8..bf imm32`: MOV immediate to a 32-bit register, zero-extending into the corresponding 64-bit register.
- `48/49 b8..bf imm64`: MOV immediate to any of the sixteen 64-bit general-purpose registers (REX.B extends the register).
- `48..4f 83 /0,/5,/7 imm8` with register-direct ModRM: ADD/SUB/CMP with signed imm8.
- `48 05/2d/3d imm32`: ADD/SUB/CMP RAX with a sign-extended immediate.
- `48..4f 89/8b/01/03/29/2b/39/3b modrm`: MOV, ADD, SUB, CMP between 64-bit registers, in both encoded operand directions. ModRM must have `mod=11`; REX.R and REX.B select extended registers. REX.X has no effect on register operands; legacy prefixes are not supported.
- `48..4f 31/33` register-direct XOR on 64-bit registers, including REX.R/B extensions; 64-bit memory XOR is not supported. XOR clears CF/OF and updates ZF/SF/PF, preserving undefined AF in this model.
- `48..4f 8d modrm`: LEA with the same effective address calculation as supported memory MOV, without accessing memory; register-direct ModRM is invalid.
- `48..4f 89/8b modrm`: 64-bit MOV between registers and memory with base, SIB index/scale, signed 8/32-bit displacement, or RIP-relative addressing. Address arithmetic wraps modulo 2^64. 64-bit arithmetic memory operands remain unsupported. Reads and writes require their respective guest permissions and failures leave CPU state and memory unchanged. Unaligned accesses are supported by this model.
- `50..5f` and `41 50..5f`: 64-bit register PUSH/POP, including RSP semantics; `e8 rel32` CALL and `c3` near RET use the guest stack. They preserve flags; stack read/write faults leave CPU state unchanged. Call/return targets are checked on subsequent instruction fetch.
- `48..4f 85 /r` TEST between 64-bit registers, register-direct only. CF and OF are cleared; ZF, SF and PF follow the AND result. AF is undefined by x86 and is preserved by this model.
- `eb rel8` and `e9 rel32` JMP, `70..7f rel8` and `0f 80..8f rel32` for all sixteen conditional branches. The displacement is sign-extended from the end of the instruction. Target arithmetic wraps as unsigned 64-bit; invalid target access is reported on the next fetch. Canonical-address checks and architectural exceptions are not modeled.

ADD/SUB/CMP update CF/PF/AF/ZF/SF/OF, preserving other modeled flag bits. CMP and TEST do not change their operands; MOV and branches do not change flags. State represents 16 general-purpose registers, RIP and RFLAGS; `reg(index)` follows x86 encoding order and returns null for indices outside 0–15. Decode and memory faults leave state unchanged. Instruction bytes require execute permission independently of read permission; this is an experimental abstraction, not a claim about console faults. No 8/16-bit registers, general 32-bit memory arithmetic or 32-bit REX register forms, 64-bit arithmetic and XOR memory operands, indirect CALL/RET variants, full stack instruction set, modes, architectural exceptions, SIMD, floating point, threading, or PS5 CPU feature model are implemented.

On Linux x86-64 with GCC/Clang, native differential tests compare immediate ADD/SUB/CMP against equivalent native register arithmetic: 20,108 cases per operation. Register-form MOV/ADD/SUB/CMP have 32,768 native-reference cases over every source/destination register and both encodings. The 64-bit imm8 ADD/SUB/CMP forms have 12,288 Linux native-reference cases covering all immediate byte values and all 16 destination registers; 32-bit register and imm8 forms have 15,360 native-reference cases. A further 320 32-bit and 1,280 64-bit portable MOV memory combinations check both directions, supported registers, displacements and access faults against expected data; they are not a native differential test. The original 29,440 portable 32-bit memory arithmetic cross-checks compare against interpreter register forms, not an independent oracle. A separate Linux x86-64 native test exercises 36,864 memory register arithmetic/TEST/XOR cases (no immediate forms), 4,096 32-bit register XOR cases and 8,192 64-bit register XOR cases against native instructions. Fault and permission cases are also checked. TEST has 8,192 native-reference cases excluding architecturally undefined AF. SIB, RIP-relative, stack and call tests are synthetic rather than native differential. Branch conditions are checked against explicit truth tables for 1,024 short/near combinations, not against a native branch oracle. Tests are not exhaustive. See TESTING.md.

Interpretation is simplest for validation but likely slow. Dynamic translation needs validated decoding, invalidation, host ABI and isolation. Native execution can be fast on compatible CPUs but demands careful protection and exception handling; a hybrid needs all of those. Synthetic interpreter benchmarks are documented in PERFORMANCE.md; they are not a comparison with another execution strategy.
